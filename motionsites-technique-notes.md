## Mostar city (cinematic scroll story)

<details>
<summary>Full prompt as copied from motionsites.ai (collapsed — reference only)</summary>

A cinematic 3-act scroll story built as a single tall section (`height: calc(100vh + 3700px)`) with a `position: sticky` inner stage. A JS engine reads scroll position every frame, smooths it via `lerp`, and writes the result into a large bank of CSS custom properties (`--bridge-y`, `--shade-opacity`, `--sights-enter-x`, etc.) that every layer's `transform`/`opacity`/`filter` references via `var()`. Named scroll "acts" are defined as pixel ranges (e.g. 560–1620px = "bridge launch + splitframes part + frame-two crossfade") using a `segmentInOut(scroll, a, b, c, d)` smoothstep helper that returns enter/exit/active values per phase, including overlapping ranges for crossfade-style handoffs between acts. Pointer position is tracked and lerped separately, offsetting background/foreground layers at different multipliers for ambient parallax independent of scroll. A full-bleed color-tinted gradient "shade" overlay ramps its top/mid/bottom alpha stops during transition moments for cinematic color grading. A card slider flies in from off-screen (`420vw` → `0`) with power-curve easing (`enter^1.55`) and is counter-scaled by `1 / backScale` so it stays screen-true while the background is simultaneously zooming for atmosphere. Slider controls only become clickable once their entrance crosses a 0.98 opacity threshold (gated interactivity). The slider itself loops infinitely via a triple-clone-the-card-set technique with instant, transition-less position jumps when the active index exits the middle set (invisible seam). `prefers-reduced-motion` is handled inside the JS engine itself (values snap instead of lerping, parallax vars forced to 0), not just via CSS media query. Full ARIA labeling, `role="button"`/keyboard handling on interactive cards, and `alt=""` on all decorative images are maintained throughout despite the heavy visual choreography. See full spec as pasted by Stephen for exact math/CSS if ever needed for reference — not reproduced verbatim here since the raw prompt lives in the plan conversation, not this file, to avoid duplicating ~500 lines of Bosnia-specific CSS/JS into the wiki.

</details>

### Extracted techniques (theme-agnostic, usable on VisionLab's site)

1. **Scroll-scrubbed choreography, not just enter-once reveals.** Instead of (or in addition to) VisionLab's existing `depth-enter` IntersectionObserver pattern (fires once, animates to a resting state), a scroll-scrubbed hero could tie element position/scale/opacity continuously to scroll *distance* within a defined pixel range — motion plays forward and backward as the user scrolls up/down, not just once on entry.
2. **Lerped/smoothed scroll value.** Don't bind animation directly to raw `scrollY` — lerp the raw value toward a smoothed one each frame (`smooth = lerp(smooth, target, 0.14)`). Produces inertial, weighted-feeling motion instead of scroll-jitter. Directly applicable to VisionLab's existing depth-enter system if it's ever extended to be scroll-scrubbed rather than trigger-once.
3. **Named "act" segments via smoothstep easing.** A small helper (`segmentInOut(scroll, rangeStart, rangeInEnd, rangeOutStart, rangeEnd)`) that returns enter/exit/active per phase is a clean, reusable pattern for choreographing a multi-beat scroll story (e.g. hero → stat reveal → CTA) with soft, overlapping handoffs instead of hard cuts.
4. **Dual-axis parallax (scroll + pointer), lerped independently.** Pointer position offsets background/foreground layers at different multipliers, smoothed separately from the scroll value — adds a subtle "alive" ambient quality even when the user isn't scrolling. VisionLab's hero (canvas warp background) could gain a very restrained version of this — pointer-driven micro-parallax on the headline or stat cards, kept subtle for a B2B audience.
5. **Progressive blur/brightness as a focus cue during transitions.** Background blur/brightness/saturation ramp tied to a transition's "active" value — draws the eye to foreground content exactly during the handoff moment, then relaxes. Could apply to VisionLab's section transitions (e.g. background canvas softly defocuses for a beat as a new section's content locks into place).
6. **Color-tinted gradient overlay with scroll-driven alpha stops.** Rather than a static overlay, the shade gradient's alpha at top/mid/bottom independently animates — cinematic color grading during specific moments rather than throughout. Directly compatible with VisionLab's existing `#nebula`/grain layer system — could gain scroll-tied intensity instead of being static.
7. **Gated interactivity tied to entrance completion.** Interactive controls (arrows, buttons) stay `pointer-events:none` until their fade-in crosses a near-complete threshold (~0.98), avoiding mid-animation clicks. Cheap, worth adopting anywhere VisionLab has a scroll-triggered CTA or control.
8. **Counter-scaling foreground UI against a zooming background.** When a background layer is being scaled for atmosphere, foreground UI (e.g. a card slider) is inversely scaled (`1 / backScale`) so it reads as screen-stable rather than swimming with the background. Useful if VisionLab ever layers UI over its canvas warp background more aggressively.
9. **Infinite-loop carousel via triple-clone + invisible instant jump.** Clone the item set 3×, start in the middle set, and when the active index scrolls past the first/third set boundary, instantly jump (no-transition) back to the equivalent middle-set position. A clean way to build a seamless looping carousel (e.g. for a future testimonial or logo strip) without modulo-wrapping mid-animation.
10. **Reduced-motion handled in the JS engine, not just CSS.** Beyond the standard `@media (prefers-reduced-motion: reduce)` transition-disabling, the engine also snaps lerped values directly and zeroes out pointer-parallax variables at the JS level — a more complete accessibility pass than typical AI output defaults to. Worth matching in any new motion VisionLab adds.
11. **CSS custom properties as the sole animation API.** JS only ever calls `style.setProperty('--x', value)`; every visual rule references `var(--x)` — never direct inline style mutation of `transform`/`opacity` strings from JS. Keeps "what animates" (CSS) cleanly separated from "how much, when" (JS timeline math) — this is effectively the same discipline as the wiki research's "explicit spec, not adjectives" tactic, applied at the code level.
12. **Accessibility maintained despite heavy choreography.** Full ARIA labels on every interactive region, `role="button"` + `tabindex` + Enter/Space keyboard handling on clickable cards, `alt=""` on all decorative imagery. A reminder that "premium and cinematic" and "accessible" aren't in tension — bake this into whatever gets built.

### Explicitly NOT carried forward (theme/content, not technique)
- Bosnia/Mostar copy, bridge/bazaar/river imagery, the 7-layer remote PNG scene stack, "Ogg Medium" font, the blue/cream color grading, the specific sights-slider content (Stari Most, Kujundziluk, etc.).
- The literal 3700px scroll-height / exact pixel breakpoints — VisionLab's own section lengths and content volume should drive any equivalent numbers, not these.

## Jack — 3D Creator Portfolio

<details>
<summary>Full prompt as copied from motionsites.ai (collapsed — reference only)</summary>

A React/TypeScript/Tailwind/Framer Motion portfolio for a 3D creator ("Jack"), dark theme, Kanit font. Five sections: Hero (massive gradient-text headline, magnetic-hover portrait image, pill CTA), a dual-row scroll-driven image marquee (rows move in opposite horizontal directions tied to scroll offset, each row tripled for seamless looping), an About section with character-by-character scroll-reveal body copy and four corner decorative images fading in from their respective sides, a white-background Services section listing 5 numbered items (huge ghost numerals beside name+description, hairline dividers, staggered fade-in per item), and a Projects section of 3 sticky-stacking cards that scale down slightly as the next card scrolls over them (Framer Motion `useScroll`/`useTransform`, `targetScale = 1 - (remaining) * 0.03`). Reusable components: `FadeIn` (single shared entrance wrapper — `viewport once, margin 50px`, one easing curve `[0.25,0.1,0.25,1]` used everywhere), `Magnet` (cursor-following magnetic hover effect on the hero portrait), `AnimatedText` (per-character scroll-tied opacity reveal). Full spec (exact Tailwind classes, colors, image URLs, dependency versions) lives in the plan conversation, not reproduced verbatim here — Jack-specific content (GIFs, portrait, Kanit font, magenta/purple CTA gradient) is theme, not technique.

</details>

### Extracted techniques (theme-agnostic, usable on VisionLab's site)

1. **Sticky-stacking cards with scroll-driven scale-down.** Each card sits in its own `position: sticky` container; as the next card scrolls up and over it, the card beneath scales down slightly (`1 - (cardsRemaining) * 0.03`) via `useScroll`/`useTransform`. Produces a tactile "stack of cards being flipped through" depth effect, distinct from VisionLab's current scroll-snap (each section is a flat full-screen swap). **Strong candidate for VisionLab's Pricing section (s8)** — the 3 tiers could stack-and-scale instead of sitting side-by-side in a static grid, giving the pricing reveal more weight. Also viable for the "VisionLab Method" (s6) steps if that section is restructured.
2. **Character-by-character scroll-reveal text.** Each character in a paragraph animates opacity 0.2→1 individually, tied to scroll progress across that paragraph's own scroll range (not the whole page) — reads as the text "resolving into focus" as you scroll past it. **Strong candidate for a pull-quote or the About/testimonial section** — more premium-feeling than a simple fade-in-once paragraph, and cheap to build (one `useScroll` + per-span opacity).
3. **Scroll-velocity-driven marquee (not constant-speed).** Instead of an autoplaying CSS `@keyframes` loop, marquee offset is computed from scroll position (`(scrollY - sectionTop + innerHeight) * 0.3`) so the strip visibly speeds up/slows with scroll speed, and two rows can move in opposite directions for a "being pulled apart" effect. VisionLab's existing tech-stack marquee (hero, s0) is currently constant-speed CSS — **this is a direct, contained upgrade candidate**: same content (Claude/Twilio/Cal.com/etc. logos), just scroll-tied instead of autoplaying.
4. **Magnetic cursor-follow on a focal image.** An element subtly translates toward the cursor when the pointer comes within a padding radius, snapping back smoothly when the cursor leaves (`ease-out` in, slower `ease-in-out` out). Restrained version could apply to VisionLab's About-section photo or a hero focal element — very small movement, but reads as "crafted."
5. **Ghost-numeral list with staggered fade-in (confirms existing pattern).** Huge low-opacity numerals (`01`, `02`...) beside each list item, staggered entrance (`delay: i * 0.1`), hairline dividers between items. VisionLab's `.phase-num` (documented in `DESIGN.md`) already does the ghost-numeral part — this confirms the pattern is current best-practice and suggests **extending the staggered-delay list pattern to the Method section (s6)** if it isn't already staggered.
6. **Layered inset+outset shadow with offset outline on the primary CTA.** Combining an inset box-shadow, an outer ambient box-shadow, AND a white outline with negative offset (`outline-offset:-3px`) creates a "glowing edge-lit" pill distinct from a flat gradient button. VisionLab's `.btn-hero` already has a two-part shadow (ring + ambient glow) — **could add the negative-offset inner outline trick** for extra edge definition without changing the existing teal glow language.
7. **Single shared entrance wrapper, one easing curve, used everywhere.** Every fade-in across the whole site routes through one `FadeIn` component with one easing curve (`[0.25,0.1,0.25,1]`) and consistent `viewport: {once:true}` semantics — total animation consistency by construction, not convention. VisionLab already does this well (`--sp`/`--sp2` used throughout) — **validates keeping to exactly two easing curves** rather than adding new ones during the upgrade.

### Explicitly NOT carried forward (theme/content, not technique)
- Kanit font, dark-to-white section color-inversion, magenta/purple CTA gradient, 3D-creator copy/imagery, the specific GIF marquee content, React/Framer Motion/TypeScript stack (VisionLab's site is vanilla HTML/CSS/JS per its Output Defaults — these techniques are all reproducible in plain JS + CSS custom properties, matching technique #11 from the Mostar city notes above).

### Extracted techniques (theme-agnostic, usable on VisionLab's site)

1. **Formal glass/material token table.** A single reference table mapping named design tokens (not just colors — full component treatments like "Primary CTA," "Left-accent badge," "Mono labels") to their exact implementation, referenced everywhere instead of improvised per component. This is the wiki research's tactic #3 ("extract a design system first") made concrete as an artifact. VisionLab's `DESIGN.md` (Step 2 of this plan) already does the color/type/spacing/shadow/motion version — **worth a small addendum**: a short component-token table (glass card, pill button, pricing card, nav) cross-referencing what's already in `DESIGN.md`'s prose into a scannable table, for faster future reference.
2. **Dedicated monospace typeface for micro-labels only.** Uppercase, wide-tracked micro-copy (badges, eyebrows, stat labels, numbered indices) gets its own typeface — distinct from both the heading and body voices — rather than just a smaller/bolder cut of the body sans. VisionLab currently uses Space Grotesk (the body sans) for `.sec-label`/`.card-label`/`.pc-tier` at small size + wide tracking. **This is a genuinely new, low-risk idea**: adding one monospace Google Font (e.g. JetBrains Mono, IBM Plex Mono, Space Mono — the last would pair naturally with the existing "Space Grotesk" name) reserved exclusively for eyebrow/label/index text would add a third distinct typographic voice without touching the existing serif-display + sans-body pairing rule.
3. **Frame-cache discipline for anything tied to continuous scroll.** Rather than repeatedly seeking a live `<video>` (or recomputing an expensive visual) on every scroll event, pre-extract/cache the discrete visual states once, then just index into the cache by scroll progress — avoids jank/stutter. Lower immediate relevance since this plan's Architecture Constraint (scroll-snap, no continuous scroll-scrub) means VisionLab isn't doing continuous scroll-tied rendering in this pass — **flagged for later** if the scroll-snap constraint is ever revisited for a specific section.
4. **Left-accent chip badge (alternate eyebrow style).** A small pill with a distinguishing left border accent (`border-l-2`) + glass background + mono label, as an alternative to a plain text eyebrow. VisionLab's hero "Now live — AI Receptionist" badge already achieves a similar effect (glass pill, dot+wave icon prefix) — confirms that treatment is on-trend. Optional: apply a left-accent-chip variant to other section eyebrows (`.sec-label`) for visual variety, low priority.
5. **Reveal system validation.** NovaAI's IntersectionObserver reveal (threshold 0.15, Y+opacity, 700ms ease-out, explicit per-element ms delays) is functionally the *simpler* version of VisionLab's existing `depth-enter` system (which already adds Z-depth translate + blur on top of Y+opacity). No new technique needed here — confirms VisionLab's existing entrance system is already at or above this bar.
6. **Explicit "Do not" list paired with the positive spec.** Stating constraints as plainly as the changes themselves (what NOT to touch) prevents scope drift during implementation. This mirrors what `premium-upgrade-spec.md` already does per-section ("Leave alone" / "Explicitly NOT doing") — validates that structure rather than introducing something new.

### Explicitly NOT carried forward (theme/content, not technique)
- The CloudFront hero video itself, "Mitha" portrait/copy, Inter font (VisionLab keeps Space Grotesk + Instrument Serif), the specific capability-panel copy, the black/white monochrome palette (VisionLab keeps its teal/orange brand colors).

## Notes for Step 4 (upgrade spec)

Techniques #1–#3 (scroll-scrubbed choreography, lerped smoothing, named-act easing) are the highest-value candidates for VisionLab's **hero section (s0)** specifically — it currently uses trigger-once `.hl` load-in, which is good but static once resolved. A restrained, B2B-appropriate version (no pointer parallax on text, modest blur/brightness shifts, no giant scale-outs) could make the hero feel considerably more alive without tipping into "flashy."

Techniques #6–#7 (scroll-tied gradient intensity, gated interactivity) are low-effort, low-risk additions compatible with the *existing* `#nebula`/`.depth-enter` systems — good candidates regardless of how ambitious the rest of the upgrade ends up being.

Techniques #13–#15 (sticky-stacking cards, character-reveal text, scroll-velocity marquee) from the Jack portfolio example fill the card/grid gap noted above — the Pricing section (s8) and hero marquee both now have concrete, well-specified upgrade candidates. Between the two examples, coverage now spans: hero (scroll-scrubbed choreography, magnetic hover), section transitions (progressive blur/gradient-tint), cards/grids (sticky-stack, ghost-numeral stagger), text (character-reveal), and CTAs (layered shadow+outline). This is enough breadth to write the Step 4 spec — no further motionsites.ai examples needed unless Stephen wants more variety for a specific section.
